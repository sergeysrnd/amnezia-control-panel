# Архитектура

## Компоненты

```text
Browser
  │ HTTPS / SSH tunnel
  ▼
Web UI (React + TypeScript)
  │ JSON API
  ▼
Control API (FastAPI + Pydantic)
  ├── inventory/read model
  ├── protocol adapters
  ├── config/QR exporter
  ├── transaction coordinator
  └── audit log (SQLite)
          │ narrow Unix-socket API
          ▼
Privileged helper
  ├── allowlisted docker exec/read/copy
  ├── atomic config replacement
  └── wg/awg syncconf
          │
          ▼
Existing official Amnezia containers
```

## Граница ответственности

Панель умеет:

- обнаруживать только известные контейнеры и интерфейсы;
- читать server config, `clientsTable` и runtime dump;
- создавать keypair клиента и выбирать свободный адрес;
- добавлять/удалять peer, переименовывать метаданные;
- генерировать клиентский конфиг/QR;
- создавать backup перед изменением и откатывать неуспешную операцию.

Панель принципиально не умеет:

- устанавливать или удалять VPN-протоколы;
- создавать, пересоздавать, обновлять или перезапускать контейнеры;
- менять server private key, subnet, listen port или AWG obfuscation-параметры;
- выполнять произвольные shell-команды;
- управлять firewall, routing, DNS или системными пакетами.

## Источники данных

1. Серверный конфиг — источник истины для состава peer-ов и адресов.
2. Runtime dump `wg/awg show <iface> dump` — источник handshake, RX/TX и endpoint.
3. `clientsTable` — только имена, даты и служебные метаданные.
4. SQLite панели — audit log, настройки UI и сведения о завершённых транзакциях; он не заменяет конфиги Amnezia.

Данные объединяются по client public key. Peer, отсутствующий в `clientsTable`, всё равно показывается как `Discovered client` и может быть именован без изменения его ключей.

## Адаптеры

Каждый адаптер задаёт фиксированные значения:

- допустимое имя контейнера;
- путь конфигурации и `clientsTable`;
- имя интерфейса;
- допустимый бинарник (`wg` или `awg`);
- parser/renderer параметров;
- генератор клиентского конфига;
- способ определения версии/возможностей.

Ни имя контейнера, ни путь, ни бинарник не принимаются напрямую из HTTP-запроса.

## Транзакция изменения

1. Получить эксклюзивную блокировку протокола.
2. Повторно прочитать конфиг и вычислить SHA-256.
3. Сохранить конфиг и `clientsTable` в backup с правами `0600`.
4. Построить новую модель в памяти и полностью её провалидировать.
5. Записать временные файлы в том же filesystem.
6. Проверить их parser-ом `wg-quick strip`/`awg-quick strip` без изменения runtime.
7. Атомарно заменить постоянные файлы.
8. Выполнить `syncconf`.
9. Перечитать runtime и убедиться, что ожидаемый public key появился/исчез.
10. При любой ошибке восстановить backup и повторно выполнить `syncconf`.
11. Записать audit event без private key и PSK.

Перед commit сверяется исходный SHA-256. Если официальный клиент изменил конфиг после шага 2, операция прекращается с `409 Conflict` и не перезаписывает его изменения.

## Создание клиента

- Private/public key генерируются криптографически безопасным генератором.
- Свободный IPv4 выбирается из server subnet по множеству фактически занятых `AllowedIPs`, а не по последней строке файла.
- PSK читается только на время сборки профиля и не попадает в логи/SQLite.
- Private key не сохраняется сервером панели по умолчанию: конфиг показывается для скачивания один раз.
- Для повторной выдачи создаётся новый peer. Опциональный зашифрованный vault — отдельная будущая функция.

## Доступ

Первая версия слушает только `127.0.0.1` и открывается через SSH tunnel. Публичная публикация, reverse proxy и многопользовательская авторизация не входят в MVP. Это уменьшает поверхность атаки до завершения security review.

## Предлагаемый стек

- Backend: Python 3.12, FastAPI, Pydantic, SQLAlchemy/Alembic.
- Frontend: React, TypeScript, Vite.
- БД: SQLite с WAL для audit/settings.
- Privileged helper: небольшой отдельный сервис с Unix socket и жёсткой схемой команд; после прототипа предпочтительно Go.
- Тесты: pytest, property-based тесты parser/renderer, Playwright для UI.
- Доставка: systemd units и воспроизводимые пакеты/образы; без монтирования Docker socket в web-контейнер.

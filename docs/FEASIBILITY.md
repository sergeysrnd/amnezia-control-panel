# Проверка реализуемости

## Вывод

Проект реализуем без создания собственного VPN-сервера. Официальные контейнеры уже содержат всё необходимое для управления peer-записями:

- постоянный конфигурационный файл интерфейса;
- JSON-файл `clientsTable` с пользовательскими именами и метаданными;
- утилиты `wg`, `awg`, `wg-quick` и `awg-quick`;
- runtime-статистику интерфейса и peer-ов.

Панель может читать эти данные, объединять их по публичному ключу и безопасно применять изменения через `syncconf`.

## Подтверждённая модель официального клиента

На ревизии `327e5985df0ef16ea03058b611e171b1d3bc0420` официального `amnezia-client`:

1. Список peer-ов извлекается из `PublicKey` в серверном конфиге.
2. Человекочитаемые имена хранятся в `/opt/amnezia/<protocol>/clientsTable` как JSON.
3. При создании клиента генерируется X25519 keypair, выбирается свободный IP и в серверный конфиг добавляется секция `[Peer]`.
4. Конфигурация применяется через `wg syncconf` или `awg syncconf`.
5. При отзыве peer-секция удаляется из постоянного конфига, обновляется `clientsTable`, затем выполняется `syncconf`.

## Матрица протоколов

| Протокол | Контейнер | Конфиг | Интерфейс | Команда |
|---|---|---|---|---|
| AmneziaWG legacy | `amnezia-awg` | `/opt/amnezia/awg/wg0.conf` | `wg0` | `wg` |
| AmneziaWG 2.0/3.1 | `amnezia-awg2` | `/opt/amnezia/awg/awg0.conf` | `awg0` | `awg` |
| WireGuard | `amnezia-wireguard` | `/opt/amnezia/wireguard/wg0.conf` | `wg0` | `wg` |

Версию AWG нельзя определять только по имени контейнера: официальный AWG 3.1 также использует имя `amnezia-awg2`. Версия определяется по набору параметров `[Interface]` и возможностям установленной утилиты `awg`.

## Что может пойти не так

- Одновременная запись из панели и официального клиента Amnezia может потерять одно из изменений. Нужны блокировка, повторное чтение перед commit и проверка hash/mtime.
- Конфиг внутри контейнера не bind-mounted. Пересоздание контейнера официальным клиентом уничтожит внесённые данные, если сам официальный workflow их не восстановит.
- Формат `vpn://` не равен обычному Base64 от `.conf`. Для AWG 3.1 необходимы golden-тесты импорта в официальных клиентах.
- Неверный public endpoint приводит к формально корректному, но нерабочему профилю. Endpoint задаётся отдельно и валидируется.
- Частичное изменение `clientsTable`, конфигурации или runtime-интерфейса требует автоматического отката.
- Код официального клиента распространяется под GPL-3.0. Нельзя копировать его реализацию в проект под несовместимой лицензией; до публикации нужно выбрать GPL-3.0 либо выполнить независимую реализацию по документированному поведению.

## Решение по первой версии

Начать с read-only панели. Запись включить только после тестов транзакций и импорта конфигов. Не предоставлять API для `docker run`, `build`, `pull`, `rm`, установки протоколов или изменения параметров серверного интерфейса.

# Создание, отзыв и восстановление

## Реализовано

Локальная панель создаёт и отзывает peer-ы в существующих официальных контейнерах.
Root-owned Python helper на VPN-хосте выполняет только фиксированные операции.
Перед записью он сверяет container ID + image ID, исходную ревизию двух файлов,
состав runtime peer-ов, публичный ключ, порт и параметры AWG.
Параметры серверного интерфейса при `syncconf` берутся из исходного runtime и
проверяются повторно после применения. Контейнеры не перезапускаются.

Профиль содержит новый клиентский keypair и PSK, свободный адрес из фактической
подсети, явно настроенный endpoint, DNS и исходные параметры AWG. Private key
клиента выдаётся один раз в HTTP-ответе и не попадает в backup или журнал.
QR содержит native `.conf`; это не `vpn://`. Импорт в конкретные версии официальных
приложений и проверка клиентского трафика остаются отдельной приёмкой.

## Установка помощника

Команды выполняются из корня репозитория. Требуется уже работающий SSH alias.
На сервере необходимы Python 3.12+ и официальные `wg/awg` tools в контейнерах.

```bash
ssh amnezia-server 'install -d -m 755 /opt/amnezia-control'
scp backend/src/amnezia_panel/mutation_core.py backend/src/amnezia_panel/remote_helper.py tools/enroll_helper.py tools/server_acceptance.py amnezia-server:/opt/amnezia-control/
ssh amnezia-server 'python3 /opt/amnezia-control/enroll_helper.py --endpoint YOUR_PUBLIC_IP --protocol wireguard --protocol awg-legacy --protocol awg'
```

Endpoint настраивается администратором; имя SSH-хоста или `hostname` не принимаются
за публичный адрес автоматически. По умолчанию DNS — `1.1.1.1`, можно передать `--dns`.
Policy хранится в `/var/lib/amnezia-control/policy.json` с правами `0600`.
После пересоздания официального контейнера требуется повторная проверка/enrollment.
При незавершённой транзакции сначала восстановите её на прежнем контейнере.

Для текущего локального режима после установки и проверок:

```bash
make dev-api-manage
# В другом терминале:
make dev-web
```

Обычный `make dev-api` сохраняет режим чтения. Не публикуйте этот локальный API
в интернете: индивидуальная аутентификация ещё не реализована. Запись защищена
проверкой Host, Origin, JSON Content-Type и случайным токеном текущего API-процесса.
Ответы имеют `Cache-Control: no-store`. Режим рассчитан на одного доверенного
пользователя компьютера. SSH-ключ пока имеет исходные root-права; forced-command
key/Unix socket, CSP, rate limits и systemd sandboxing — следующий этап hardening.

## Транзакция

1. Helper берёт неблокирующий `flock` на протокол.
2. Проверяет незавершённые операции и восстанавливает их до следующей записи.
3. Сверяет ревизию из формы с конфигом и `clientsTable`; несовпадение — `409`.
4. Проверяет контейнер, схему, занятые адреса и согласованность runtime.
5. Строит кандидат, проверяет строгим parser-ом и native `*-quick strip`.
   `strip` сам по себе не является полноценной проверкой конфигурации ядром.
6. Сохраняет исходные/ожидаемые файлы и runtime в приватную директорию транзакции.
7. После повторной сверки атомарно заменяет каждый файл через временный файл
   на том же filesystem и `mv`, выполняя `sync` до/после замены.
8. Применяет `syncconf`, перечитывает файлы, весь состав peer-ов и серверный интерфейс.
9. При ошибке восстанавливает исходные файлы и runtime, затем проверяет результат.

Два файла не заменяются одной атомарной операцией. Между заменами возможен сбой;
его покрывают write-ahead journal и rollback. Backup/journal лежит вне контейнеров:

```text
/var/lib/amnezia-control/<protocol>/<operation-uuid>/
  config.before / table.before / runtime.before
  config.after  / table.after  / runtime.after
  state.json
```

Каталоги имеют права `0700`, файлы — `0600`. State содержит действие, время,
container ID, непрозрачный peer ID, хэш запроса и результат. Конфиги/PSK находятся
только в приватных файлах backup, не в `state.json`. Автоматической ротации пока нет.

## Сбой или потеря связи

Каждая запись имеет UUID. Повтор с тем же UUID не создаёт второй peer и не выдаёт
приватный ключ повторно. При потере ответа используйте «Проверить состояние
операции»; не создавайте дубликат вслепую. Если создание завершено, а профиль
потерян, отзовите именно это подключение и создайте новое.

Если helper обнаружил прерванную запись, форма предлагает «Восстановить прерванную
операцию». Это защищённый POST; GET/preflight/status не изменяют VPN-конфиги.
Восстановление также запускается перед следующей операцией записи.

Если при откате обнаружены чужие изменения или заменён контейнер, helper
оставляет `recovery_required`, сохраняет backup и блокирует запись. Нужна ручная
проверка администратором: нельзя безусловно копировать старую конфигурацию поверх
новых изменений. Автоматический откат не может гарантировать успех при отказе
диска, недоступности Docker или продолжающейся сторонней записи.

## Совместная работа с официальным клиентом

Официальный клиент не берёт блокировку панели. SHA-256 и повторные чтения
обнаруживают изменения на контрольных точках, но между проверкой и rename
остаётся окно гонки. Во время управления подключениями используйте только один
редактор: панель или официальный клиент. Полная сериализация потребовала бы
участия обоих писателей, которой штатный клиент не предоставляет.

## Проведённая приёмка

2026-09-05: native создание/удаление синтетического peer-а в изолированной сети
прошло для WireGuard, AWG Legacy и установленного AWG 2.x. Затем отдельные
временные peer-ы созданы и отозваны через production helper во всех трёх
контейнерах; исходные составы 1 / 30 / 17, метаданные и параметры сохранены.
Проверен реальный UI цикл WireGuard: preflight → создать → файл/QR → подтвердить
имя → отозвать → отсутствие тестового peer-а. Тестовые подключения удалены;
резервные копии транзакций оставлены на сервере.
Дополнительно в WireGuard намеренно вызвана ошибка после реального `syncconf`:
helper вернул `rolled_back`, оба файла восстановлены побайтно, исходный runtime
peer сохранён. Инъекция доступна только в отдельном root acceptance-скрипте;
HTTP API не предоставляет функции создания искусственных сбоев.

AWG 3.1 export-поля покрыты тестами преобразования, но live-контейнера этой версии
в данной приёмке не было. Работа профиля через сеть клиента ещё не проверялась.

Для повторной приёмки (lifecycle изменяет только собственный временный peer):

```bash
ssh amnezia-server 'python3 /opt/amnezia-control/server_acceptance.py isolated wireguard'
ssh amnezia-server 'python3 /opt/amnezia-control/server_acceptance.py lifecycle wireguard'
ssh amnezia-server 'python3 /opt/amnezia-control/server_acceptance.py rollback wireguard'
```

Протокол можно заменить на `awg-legacy` или `awg`. Исходные файлы не выгружаются
в репозиторий, тестовый вывод не содержит ключей и имён существующих клиентов.

# План работ

## Этап 0 — контракты и тестовые данные

- Зафиксировать схемы AWG legacy, AWG 2.0, AWG 3.1 и WireGuard.
- Получить обезличенные fixtures конфигов и `clientsTable` без реальных ключей.
- Зафиксировать runtime dump для каждого протокола.
- Описать JSON API и ошибки до реализации UI.
- Решить лицензию до копирования любого GPL-кода.

Критерий: parser/renderer contracts и набор безопасных fixtures прошли review.

## Этап 1 — read-only MVP

- Discovery известных контейнеров.
- Определение AWG generation по возможностям и параметрам, а не имени.
- Чтение и нормализация config + `clientsTable`.
- Runtime handshake/RX/TX/endpoint.
- UI списка протоколов и клиентов.
- Health/readiness и редактирование только локального отображаемого имени в БД панели.

Критерий: панель видит всех существующих клиентов на текущем сервере и ничего не меняет внутри контейнеров.

## Этап 2 — безопасные изменения

- Protocol-level lock и optimistic concurrency по SHA-256.
- Backup/atomic write/rollback.
- Переименование с совместимым обновлением `clientsTable`.
- Создание peer-а и удаление/revoke.
- Проверка runtime после `syncconf`.
- Audit log.

Критерий: failure-injection тесты на каждом шаге не оставляют config и runtime в разных состояниях.

## Этап 3 — экспорт подключений

- Native `.conf` для WireGuard, AWG legacy, AWG 2.0 и AWG 3.1.
- QR-код с контролем размера/error correction.
- Точное кодирование официального `vpn://`.
- Golden-тесты импорта в AmneziaVPN Android, iOS, Windows и Linux.
- Валидация public endpoint и UDP-порта.

Критерий: профиль, созданный панелью, импортируется официальным приложением и передаёт трафик для каждого поддержанного поколения.

## Этап 4 — production hardening

- Разделение web backend и privileged helper.
- Systemd sandboxing, Unix socket permissions, backup retention.
- Аутентификация, CSRF/CSP/rate limits.
- Обновление без потери audit DB.
- Документированный disaster recovery.
- Security review и dependency scanning.

Критерий: установка на рабочий сервер не требует Docker socket в web-процессе и не предоставляет произвольного shell execution.

## Этап 5 — дополнительные возможности

- Несколько серверов через agent/SSH transport.
- Группы и сроки действия клиентов.
- Ограничение трафика без вмешательства в VPN-контейнеры — только после отдельного дизайна.
- Зашифрованный vault для разрешённого повторного скачивания профилей.
- Уведомления и API tokens с ограниченными ролями.

## Порядок пилота на текущем сервере

1. Установить официальный AWG 3.1 и проверить его штатным клиентом.
2. Снять обезличенные fixtures всех трёх поколений.
3. Развернуть read-only панель на `127.0.0.1`.
4. Сравнить найденных peer-ов с официальным приложением.
5. Создание/отзыв сначала тестировать на отдельном контейнере или VPS.
6. После golden-тестов включить запись для одного тестового peer-а на рабочем сервере.

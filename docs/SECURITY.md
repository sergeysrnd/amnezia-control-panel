# Безопасность

Панель работает с VPN-ключами и потенциально получает root-возможности через Docker, поэтому безопасность является частью MVP, а не последующим улучшением.

## Обязательные ограничения

- Web API по умолчанию доступен только на loopback.
- Ни один HTTP-параметр не интерполируется в shell-команду.
- Контейнеры, пути, интерфейсы и бинарники выбираются только из compile-time allowlist.
- Web-процесс не получает `/var/run/docker.sock`.
- Privileged helper принимает типизированные операции, а не строки команд.
- Client private keys и PSK никогда не пишутся в логи, audit DB или telemetry.
- Конфиги и backup имеют права `0600`, каталоги — `0700`.
- Любая операция записи создаёт backup и имеет проверенный rollback.
- В UI опасные операции требуют явного подтверждения с именем клиента и протокола.
- CSRF-защита, secure cookies, rate limiting и строгий CSP обязательны до публичного HTTPS-доступа.

## Модель угроз

Защищаемся от:

- command/path injection через API;
- подмены контейнера с ожидаемым именем;
- утечки private key через журнал, exception или browser history;
- race condition с официальным клиентом;
- повреждения конфига при частичном сбое;
- SSRF/произвольного SSH-доступа к другим хостам;
- повторной выдачи одноразового клиентского секрета;
- захвата административной сессии.

## Проверка идентичности контейнера

Одного имени недостаточно. Adapter сверяет имя, ожидаемые файлы, доступные команды, interface type и fingerprint Docker image/config schema. При несовпадении протокол переводится в read-only режим.

## Секреты клиента

Создание peer-а возвращает приватный материал только один раз. До подтверждения скачивания операция может быть отменена. После подтверждения backend очищает временный объект и хранит только public key, IP и несекретные метаданные.

## Аудит

Храним: время, локального администратора, действие, протокол, public-key fingerprint, IP, результат и backup ID. Не храним: полный public key при ненужности, private key, PSK, содержимое QR и полный клиентский конфиг.
